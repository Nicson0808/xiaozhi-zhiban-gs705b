# 03 运维与坑

跑起来只是开始。这一篇是长期稳定运行的几个关键点，全部来自实测。

## 3.1 日志会写满分区（必须处理）

`/var/upgrade` 只有 9.8MB，`xiaozhi.log` 实测约 **3MB/天**（每 5 秒一条内存统计），
**3 天写满**。写满后 sair 可能崩溃，看门狗连续失败会把设备回退到原厂。

`scripts/log_rotate.sh` 每 10 分钟检查一次，超 512KB 用 **copytruncate** 裁到 200KB：

```sh
tail -c 200000 "$LOG" > /tmp/.logtail && cat /tmp/.logtail > "$LOG"
```

为什么能安全 copytruncate：sair 以 `O_APPEND` 打开日志（`/proc/<pid>/fdinfo` 里 `flags: 02001`），
截断后写入自动落到新末尾，不会产生空洞。

部署后分区占用稳定在 1.2MB 左右。

## 3.2 会话五分钟后自动结束

现象：聊到一半"自己退了"。日志对得上：

```
[11:11:42] 会话开始
[11:16:44] Listening → Cleaning → Idle     # 正好 302s
```

原因：`session_timeout` 默认 300000ms。改法：

```bash
curl -X PUT -H "Content-Type: application/json" \
     -d '{"session_timeout":900000}' \
     http://<device-ip>:8080/api/assistant/config
```

**注意**：这个字段存在 `/tmp/sair_config.json`，重启即丢。
所以配 `scripts/boot_config.sh`，开机 30 秒后用 `printf | nc` 回写。

## 3.3 telnet 默认开放 = 裸奔

`telnetd -p 23` 是**无密码 root shell**，同一局域网任何设备可进。
`scripts/test.sh` 把它限制为**开机后 15 分钟窗口**：

```sh
busybox telnetd -p 23 -l /bin/sh
( sleep 900; killall telnetd 2>/dev/null ) &
```

需要远程 shell 时：`POST /api/reboot` 重启 → 15 分钟内连上。

8080 面板没有鉴权，但只能做配置/重启/文件读写，不能执行任意命令。

## 3.4 备份与恢复

`/var/upgrade` 全量备份后（见 `scripts/restore.sh`），随时可一键还原：

```bash
sh restore.sh <device-ip>
```

备份内容：`sair`、`xwebd`、`test.sh`、`log_rotate.sh`、`boot_config.sh`、
`boot_watchdog.sh`、`watchdog_guard.sh`、`use_limit_exhausted.mp3`。

校验方法：`md5sum` 比对设备端 `/var/upgrade/sair`。

## 3.5 坑清单

| 坑 | 现象 | 解法 |
|---|---|---|
| busybox `nc` 是精简版 | 写 `nc -w 5 IP PORT` 直接打印 usage | 只写 `nc IP PORT` |
| `kill -9 sair` | **整机重启**（不是重启助手） | 想换配置只能重启设备 |
| `kill launcher` | 同样整机重启 | 别单独杀 UI 进程 |
| 8080 直连 PUT 报 `Invalid JSON body` | 用 `--data-binary @file` 时出现 | 改用 `-d '{"key":val}'` 内联 |
| 设备无 RTC | 重启后日志时间戳回跳 | OTA 校时后自动恢复，不影响功能 |
| USB 会掉线 | `adb devices` 突然空 | 改用 8080 通道，功能等价 |
| 上传后文件权限 | vfat 自动 755 | 不需要 chmod |
| 唤醒词喊不醒 | 说「你好小智」无反应 | 这台机器只认「智伴智伴」 |

## 3.6 资源红线

- 空闲内存仅 1–2MB，不要在上面跑额外服务
- 负载常态 5–10（4 核 A5），机身会热，别堵背部散热孔
- 电池老化后掉电快，长期使用建议插电
